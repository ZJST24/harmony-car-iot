1五端技术栈总表

下面每张表都回答同一个问题：这个技术在本项目里具体替我们做了什么。版本号均为本机实测值，不是文档抄来的。

① 模拟小车端 · server/car_mqtt_client_001.py

技术 / 版本用在哪作用（为什么非要它）
Python 3.10.21
D:\miniconda\python.exe		整个车端脚本的运行环境华为云 SDK 与 paho 都在这个解释器里；裸 python 是 3.13，装不了也导不进这些包。
paho-mqtt 2.2.0CONNECT / SUBSCRIBE / PUBLISH / loop_startMQTT 协议客户端。没有它就得手写 TCP 报文；它还负责断线回调、QoS 重发、后台收消息线程。
hmac + hashlib
标准库		mqtt_credentials()生成一机一密的登录密码：hmac_sha256(key=UTC小时戳, msg=device_secret)。云平台用同一算法验签，密码不用在网络上传密钥。
ssl
标准库		tls_set(CERT_NONE) / tls_insecure_set把 MQTT 包在 TLS 里走 8883 端口。教学环境跳过了服务端证书校验（生产不能这么写）。
json / time / math / datetime上报载荷、运动模型、UTC 时间位置、朝向、电量全靠 math.sin/cos 按 speed×0.2 px/s 推算；datetime.utcnow() 保证时间戳是 UTC（写成本地时间会 rc=4）。
IoTDA 预定义主题
$oc/devices/…		属性上报 / 命令订阅 / 命令回执云端规定好的「信箱地址」，见下方 A4。主题写错云端直接丢弃，且不报错。
MQTTS · QoS 1 · 8883全链路传输QoS 1 = 至少送达一次，命令和属性都不允许悄悄丢。

② 华为云 IoTDA（云端，无本地代码）

技术 / 版本用在哪作用（为什么非要它）
标准版免费单元 S0
9f149bee02 / cn-north-4		设备接入实例提供 1000 设备 / 每日 1 万条消息的免费额度。标准版必须用实例专属域名，用通用域名恒定 403。
物模型 Product Model
service_id = car		model/smart-car-model.zip云端的「设备说明书」：声明 5 个属性（x/y/heading/speed/battery）和 5 个命令。没上传它，属性和命令都不被识别。
设备影子 Device ShadowShowDeviceShadow / /status云端保存的「最后一次上报状态」。车离线也能读到旧坐标 —— 这是本项目用轮询而不是长连接的根本原因。
一机一密 device_id + secret车端 CONNECT每台设备独立密钥，泄露一台不影响其他设备；与 AK/SK 是两套完全不同的凭证。
AK / SK + IAM + project_id后端调应用侧 OpenAPI账号级长期凭证，用于给每个 HTTPS 请求签名。project_id 是区域级项目 ID，不是账号 ID。
V11 衍生签名
with_derived_predicate		SDK 的 BasicCredentials标准版实例专属端点要求的签名变体。少了它，即使 AK/SK 正确也 403。
同步命令 CreateCommand/command 背后后端发命令后阻塞等车端回执（约 0.3~20 秒），所以返回 executed:true 代表真的执行了，不是「已发送」。

③ 业务后端 · server/app.py

技术 / 版本用在哪作用（为什么非要它）
Flask 3.1.3@app.get/post、jsonify把三个业务接口 + 两个页面路由暴露成 HTTP 服务。轻量、单文件、无需数据库。
after_request CORS 钩子add_cors()给所有响应补 Allow-Origin / Allow-Headers / Allow-Methods，让 file:// 打开的网页也能 POST JSON（否则 OPTIONS 预检被拦）。

huaweicloudsdkcore/iotda 3.1.221IoTDAClient.new_builder()封装签名、序列化、重试、异常。自研要手写 AK/SK 签名算法，成本极高。
BasicCredentials + Region客户端初始化（约 70~80 行）把「账号凭证 + 项目 + 专属端点」装进客户端。这三样加「请求不带 instance_id」合称认证四要素。
Decimal → floatshadow_to_state()SDK 把影子里的数值返回成 Decimal，jsonify 不认识，必须转 float，否则 500。
logging 双 Handler控制台 + commands.log命令与回执留痕，是「管控点」的证据，也是排错时唯一的时间线。
命令白名单 + 0~100 校验build_paras()非法命令在后端就被 400 拒绝，不让它到达云和车。

④ 鸿蒙 APP · D:\harmony-project\ohcar

技术 / 版本用在哪作用（为什么非要它）
HarmonyOS 6.0.2(22) / API 22build-profile.json5编译与运行的目标 SDK 版本，决定能用哪些 API。

⑤ 视图端 · web/*.html

技术 / 版本用在哪作用（为什么非要它）
原生 HTML/CSS/JS（零依赖）两个页面单文件双击即开，不需要构建、不需要 npm。用来在写 APP 之前低成本验证接口。
fetch + cache:"no-store"轮询 /status、POST /command禁用缓存，保证每次拿到的是新影子，不是浏览器缓存的上一次结果。
setInterval(2000)两个页面2 秒轮询是免费额度和流畅度的折中；影子本身运动 5 秒 / 静止 60 秒才更新，轮更快也没有新数据。
requestAnimationFrame + Canvas 2Dcar_console.html每帧重绘做航位推算平滑；car_cloud_view.html 更简，只在轮询后重绘。
键盘事件 / D-pad / 指令日志car_console.htmlWASD、方向键、空格停车；每条命令记下耗时 ms 与 executed，相当于可视化 commands.log。
横切技术（不属于任何一端，但五端都受影响）：坐标系约定（heading=0 朝上 → 前进时 y 减小）、世界尺寸 800×600、速度 speed×0.2 px/s、时间一律 UTC、云端影子的 time 格式 20261107T083726Z。这些约定散在 5 个文件里，改一处必须五处同步 —— 详见接口文档「统一数据约定」。

2关键技术点：作用与位置

按学习地图的 5 个「面」分组，每个卡片回答三件事：它做什么 · 代码在哪 · 少了它会怎样。编号与 00-学习地图 的知识点编号对齐，以后说「讲 B4」就能直接定位。

面 A · 物联网通信 MQTT ★★

A1发布 / 订阅与主题路由
车端不连后端、后端不连车端，双方只跟云端的「主题」收发消息，彼此解耦。
位置 on_connect 订阅 / publish 上报 · 少了它 就得端到端直连，无法一对多、无法离线缓存。
A2一机一密（HMAC-SHA256）
用 secret 和 UTC 小时戳算出临时密码，密钥本身从不上网；clientId 带时间戳防止重放。
位置 mqtt_credentials() 137~144 行 · 少了它 CONNECT 返回 rc=4（用户名或密码错误）。
A3MQTTS / TLS 8883 / QoS 1
传输加密 + 至少送达一次。命令与属性都不允许静默丢失。
位置 tls_set + loop_start() · 注意 CERT_NONE 跳过证书校验，只适合教学环境。
A4三条预定义主题
properties/report 上报、commands/# 收命令、commands/response/request_id=… 回执。回执的 request_id 藏在命令主题尾部，靠字符串切出来。
位置 on_command() 192~210 行 · 少了它 后端永远等不到回执，executed:false。

面 B · 华为云 IoTDA ★★★

B1物模型 service_id=car
定义设备「能报什么、能收什么」。5 属性 + 5 命令是两端共同的语法，service_id 由后端写死。
位置 model/smart-car-model.zip 上传到控制台 · 少了它 上报被拒、命令报「命令不存在」。
B2设备影子
云端保存的最后一份状态快照。/status 读的是它，不是实时推送；车离线时 x/y 是旧值。
位置 app.py: shadow_to_state() · 理解它 才明白为什么 APP 用轮询而不是长连接。
B3实例专属端点（两个域名）
设备侧 iotda-device 给车端连 MQTT，应用侧 iotda-app 给后端调 OpenAPI，两者不能混用。
位置 config.json: endpoint / 车端 ENDPOINT · 用错 恒定 403 或连不上。
B4认证四要素 / 403 破案
AK/SK + project_id + 专属端点 + 衍生签名，且请求不带 instance_id。缺一即 403 IOTDA.000021，报错还骗你说「用户不存在」。
位置 app.py 70~80 行 · 排错 跑 test_api_auth.py 的 2×2 矩阵，一次定位。
B5同步命令与回执
CreateCommand 会挂起等车端回 response，所以 executed:true = 物理上真的动了，不是「已投递」。
位置 app.py /command · 耗时 实测 300~400ms，最坏约 20 秒超时。

面 C · Python 后端 ★★

C1Flask 路由 + jsonify
3 个业务接口 + 3 个页面路由，全部无状态、无数据库，配置只在启动时读一次。
位置 app.py 151~217 行 · 注意 debug=False，改代码必须手动重启。
C2命令白名单（管控点）
只允许 5 个命令、speed 必须是 0~100 整数，非法请求 400 挡在后端，不到云、不到车。
位置 build_paras() · 意义 APP 零凭证 + 后端唯一管控，是这套三层架构的安全基础。
C3CORS 与同源托管
after_request 放行来源 + 头 + 方法；再由 send_from_directory 把网页挂在后端域名下，双击打开也能用。
位置 add_cors() / console_page() · 少了它 网页 POST JSON 被 OPTIONS 预检拦死。
C4SDK Builder + 自建 Region
把凭证、衍生签名、专属端点装进 IoTDAClient；Region(id, endpoint) 是覆盖通用域名的关键写法。
位置 app.py 73~80 行 · 版本 3.1.221 已修复旧版打包 bug，无需手动打补丁。
C5审计日志与异常翻译
logging 同时写控制台和 commands.log；云端异常统一转成 502 并带 error_msg。
位置 app.py 58~66 行 · 用途 出问题时唯一可回溯的时间线。
C6Decimal 序列化
SDK 影子数值是 Decimal，jsonify 不认，逐字段转 float 才能返回 JSON。
位置 shadow_to_state() · 少了它 /status 直接 500。

面 D · 鸿蒙 ArkTS / ArkUI ★★★

D1@State / @Prop 状态驱动
父组件 @State 变化会单向同步到子组件 @Prop，UI 自动重建。
踩过的坑 原来用 @Builder 按值传参，六项指标被永久固化成 --；画布是命令式绘制反而正常，掩盖了问题。
D2@ohos.net.http 短连接
createHttp → request → destroy，连接超时 4s / 读取 12s，非 200 抛出带后端 error 原文的异常。
位置 CarApi.ets · 约定 不做长连接、不引 STATE 流。
D3PersistentStorage / @StorageLink
后端地址持久化，模拟器 10.0.2.2:8000、真机改局域网 IP，重启不丢。
位置 Index.ets 16 / 146 行 · 注意 换网络后 IP 会变，要重新在 ⚙ 里改。
D4Canvas + 航位推算双定时器
setInterval(2000) 拉真实影子，setInterval(100) 按速度朝向外推位置，影子到达立刻校正（白圈=真实点）。
位置 aboutToAppear() / drawField() · 现象 画面「漂移再跳回」是正常校正。
D5权限与明文放行
ohos.permission.INTERNET + network_security_config 允许 http://。华为云侧仍是 HTTPS + AK/SK。
位置 module.json5 / network_config.json · 少了它 报 2300007 类网络错误。
D6hvigor / HAP / 签名
命令行编译产出 entry-default-unsigned.hap（约 228K），需 DevEco 自动签名才能装机。
现状 已零警告编译通过，模拟器实测运行过；CLI 无法代做签名。

面 E · 工程化与调试 ★★

E1解释器与依赖隔离
所有包都装在 D:\miniconda\python.exe(3.10.21)；README 写的 D:\anaconda3\ 在本机不存在，裸 python 是 3.13。

E2地址与端口

E3分层排错矩阵

E4凭证分层存放
AK/SK 只在后端 config.json；device_id/secret 只在车端；APP 零凭证。泄露半径最小。
现状 根目录 明文凭证/ 存着 4 份敏感文件的备份，交作业前需另行处理。

    5哪些是过程性测试文件

    这是你问的重点。所谓「过程性」，指为了解决某个具体问题临时写出来、或者由工具自动生成、不属于最终产品的文件。它们记录了项目的演进历史，但对运行没有贡献。

    server/test_accounts.py横向对比多个 IAM 账号谁能调通基本用不上（你只有一个账号）保留作教学素材。旧版曾硬编码 4 组老师 AK/SK，2026-11-07 已清除。

    6按链路看文件（线的视角）

    把文件摊在目录树里是「面」；按一次点击的顺序串起来是「线」。下面这条 FORWARD 的下行链路，走完就理解了文件之间真正的依赖关系。

    线 1 · 点一次「前进」，经过了哪些文件

    Index.ets
    PadBtn.onTap    → CarApi.ets
    sendCommand    → HTTP POST /command→ app.py
    build_paras 白名单    → config.json
    取 AK/SK    → SDK → IoTDA
    CreateCommand    → MQTT commands/#→ car_mqtt_client_001.py
    on_command

    回程是反方向：车端发 commands/response/request_id=… → 云端 → 后端把 executed:true 返回 → CarApi 解析 → Index.ets 显示「✓ FORWARD 已执行（383 ms）」并写进指令记录。

    线 2 · 画面上那个点为什么会动

    001.py 运动模型
    每秒算坐标    → properties/report
    5s / 60s 上报    → 设备影子→ app.py /status→ CarApi.getStatus
    2s 轮询    → Index.ets Canvas
    100ms 航位推算    → car_console.html
    同源展示
    两条线是不同步的，这正是「漂移再跳回白圈」的原因：上报 5 秒一次、APP 拉取 2 秒一次、绘制 100ms 一次。三层频率必须靠航位推算弥合。理解这一点，就理解了为什么项目选轮询 + 影子，而不是长连接。

    线 3 / 4 · 另外两条线涉及的文件

    主线涉及文件说明
    线 3 · 设备上线鉴权car_mqtt_client_001.py（mqtt_credentials）、明文凭证/DEVICES-KEY-…txt、控制台注册的设备一机一密的三个输入：device_id、secret、UTC 小时戳；与 AK/SK 无关。
    线 4 · 后端调云凭证server/config.json、app.py 70~80 行、test_api_auth.pyAK/SK → 衍生签名 → 专属端点 → 项目 ID；instance_id 只写在配置里做记录，不进请求。
