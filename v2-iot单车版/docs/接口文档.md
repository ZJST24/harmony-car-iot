## 1. 全局：五端四条链路

```
   ┌──────────────┐                        ┌──────────────┐
   │  ① 鸿蒙 APP   │                        │ ⑤ 视图端(浏览器)│
   │  零云凭证      │                        │  零云凭证      │
   └──────┬───────┘                        └──────┬───────┘
          │  I-01~03  HTTP/JSON                    │  I-04~06  HTTP/JSON
          └───────────────┬───────────────────────┘
                          ▼
                 ┌────────────────┐
                 │ ② 业务后端 Flask │  持有 AK/SK · 白名单 · 审计
                 └────────┬───────┘
                          │  I-07~09  HTTPS OpenAPI（AK/SK 签名）
                          ▼
                 ┌────────────────┐
                 │ ③ 华为云 IoTDA  │  设备影子 · 命令下发 · 物模型
                 └────────┬───────┘
                          │  I-10~14  MQTTS / TLS 8883
                          ▼
                 ┌────────────────┐
                 │ ④ 模拟小车 MQTT │  device_id + secret
                 └────────────────┘
```

**核心设计原则：凭证只在需要它的那一层。**
APP 和网页只认一个 `http://...:8000`，拿不到也存不了 AK/SK；云端凭证只在后端；设备密钥只在小车端。

## 2. 数据契约（全链路统一）

所有端对同一组字段用同一套语义，改一处要五处同步。

| 字段 | 类型 | 范围 | 含义 |
|---|---|---|---|
| `x` | number | 10 ~ 790 | 场地横坐标（场地 800×600） |
| `y` | number | 10 ~ 590 | 场地纵坐标，**向下增大** |
| `heading` | number | 0 ~ 359 | 朝向，**0 = 朝上**，顺时针增大（90 = 朝右） |
| `speed` | number | -100 ~ 100 | **带符号**：正=前进，负=后退，0=停 |
| `battery` | number | 20.0 ~ 100 | 电量百分比，最低兜底 20.0 |
| `time` | string | — | 影子事件时间，UTC 紧凑格式 `20261107T092226Z` |

**方向约定**：`heading=0` 朝上 → 前进时 `y` **减小**，这是最容易看错的一点。
**时间约定**：云端一律 UTC；只有小车日志用本地时间。APP 里的"影子上报 N 秒前"就是拿 `time` 换算出 UTC 再求差的。

## 3. ①② 与 ⑤② 之间：HTTP 接口（同一个后端，两拨客户端）

> 三条业务接口对 APP 和网页是**完全一样**的，区别只在调用者：
> - APP：`@kit.NetworkKit` 的 `http`，原生请求，没有 CORS 概念
> - 网页：浏览器 `fetch`，受同源策略约束（本工程已解决，见 I-06）

### 通用约定

- 基础地址：模拟器 `http://10.0.2.2:8000`；真机/网页 `http://<电脑局域网IP>:8000`；本机 `http://127.0.0.1:8000`
- 请求头：`Content-Type: application/json`；v1.5 起可带 `X-Auth-Token: <token>`（也接受 `Authorization: Bearer <token>`）
- 响应头：`Access-Control-Allow-Origin: *`、`Allow-Headers: Content-Type, X-Auth-Token, Authorization`、`Allow-Methods: GET, POST, OPTIONS`、`Max-Age: 600`
- 错误响应统一形状：`{"ok": false, "error": "人类可读的原因"}`；鉴权失败额外带 `"stage": "auth"`
- 时间单位一律毫秒/秒在文档里写明，不靠猜

### 多车约定（v1.3 起，适用于 I-01 / I-02 / I-03 / I-15）

| 项 | 约定 |
|---|---|
| 传参 | GET 用 `?device_id=`；POST 用 JSON body 或 multipart form 的 `device_id` 字段 |
| 不传 | 回落 `devices.json → default`，**旧 APP / 旧 curl 零改动**，行为与单车时代完全一致 |
| 校验 | 服务端只认台账里登记且 `enabled=true` 的 ID；未登记 / 停用一律 `400 {"ok":false,"error":"设备未登记：…"}` |
| 返回 | `/health`、`/status`、`/command`、`/voice_command` 均新增 `device_id`；`/status` 另增 `device_name` |
| 审计 | `commands.log` 每条写成 `命令下发 -> [device_id] CMD …`，可区分是哪台车 |
| 安全 | 客户端不能凭空指定任意设备 ID 绕过台账，这是多车第一道闸门 |

**实测验收（2026-11-08）**：001 下发 `FORWARD 30` → `executed:true`，2 秒后 001 `speed=30`、002 仍 `speed=0 / x=200`，无串台；002 下发 `STOP` → `executed:true`；未登记 ID → 400。

### 鉴权约定（v1.5 / M2 起，适用于所有 HTTP 接口）

| 项 | 约定 |
|---|---|
| 身份来源 | 请求头 `X-Auth-Token`；也接受 `Authorization: Bearer <token>` 与 `?token=`（后两者仅供 curl / 旧 APP 演示） |
| 身份台账 | `server/access.json`：user / token / role / `devices`（可控制列表）/ `scope`（可见范围）。**token 只存后端**，与 AK/SK 分开存放 |
| 不带 token | `require_token=false`（默认兼容模式）视为 `anonymous` 访客，旧 APP / curl 零改动；设 `true` 则一律 401 |
| token 无效 | `401 {"ok":false,"stage":"auth","error":"身份令牌无效…"}`；账号停用 `403` |
| 裁决顺序 | `before_request` 解析身份 → `resolve_device()` 台账校验 → **写接口再 `guard_control()` 逐次校验 `(身份, device_id)`** → 才允许下发 |
| 越权 | `403 {"ok":false,"stage":"auth","error":"身份「…」无权控制 …（403）"}`，并写 `commands.log` 的「越权拒绝」 |
| 可见 vs 可控 | 刻意分开：`scope=all` 能看见全部车（多车同屏不退化），但只有 `devices` 命中的车能下发；`scope=bound` 连查看也只放行自己绑定的车 |
| 接口过滤 | `/devices`、`/fleet_status` 按可见范围裁剪，每台车带 `can_control`；`/status`、`/health` 单台越权查看返回 403；`/voice_command` 即使只解析也要过控制权校验 |
| 审计 | 每条命令写 `user=xxx [device_id]`，越权与无效 token 同样留痕；token 本身绝不进日志 |
| 热加载 | `access.json` 按 mtime 自动重载，`access_admin.py` 改绑定后下一请求即生效，无需重启 |

**四种演示身份**（真实 token 只在 `access.json`，不写进文档；交作业前用 `access_admin.py rotate` 轮换）：

| 身份 | 角色 | 可控制 | 说明 |
|---|---|---|---|
| 访客（不带 token） | operator | 1 号车 | 旧客户端行为不变；控 2 号车会被 403 拦下 |
| `teacher` | admin | `*` 全部 | 教师端 |
| `group1` / `group2` | operator | 各绑定 1 台 | 分组教学，越权操作可直接演示 |
| `observer` | viewer | 无 | 只看不控，任何下发都 403 |

> **教学红线**：前端把按钮灰掉、把车藏起来都**不算授权**。服务端必须在每次下发前重新校验 `(身份, device_id)`，否则换一个 curl 就能绕过。

### I-01 `GET /health` —— 探活 + 设备在线

**谁调**：APP 启动时打一次，用来点亮右上角"车在线"徽标。
**底层**：后端调一次 `ShowDevice`（I-07），看 `status` 字段。

**请求**：无参数、无 body。

**响应 200**

```json
{"ok": true, "device_online": true}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | bool | 后端自身存活（能返回就一定是 true） |
| `device_online` | bool | 设备状态是否为 `ONLINE`；云端调用异常时降级为 `false` |

**注意**：`ok:true` + `device_online:false` 是常见组合，意思是"后端活着，但小车没连上"。

### I-02 `GET /status` —— 拉最新状态（APP 轮询）

**谁调**：APP 每 **2 秒**轮询一次；网页同样 2 秒。
**底层**：后端调 `ShowDeviceShadow`（I-08）+ `ShowDevice`（I-07），**一次请求打两次云 API**。

**请求**：无参数。
（页面用 `fetch(url, {cache:'no-store'})` 禁用缓存，避免拿到旧坐标。）

**响应 200**

```json
{
  "ok": true,
  "online": true,
  "x": 427,
  "y": 312,
  "heading": 135,
  "speed": 0,
  "battery": 83.2,
  "time": "20261107T092226Z"
}
```

| 字段 | 类型 | 可能为 null | 说明 |
|---|---|---|---|
| `ok` | bool | 否 | — |
| `online` | bool | 否 | 设备当前是否在线 |
| `x` / `y` | number | 是 | 影子里的坐标；设备从未上报过则为 `null` |
| `heading` | number | 是 | 0~359 |
| `speed` | number | 是 | 带符号 |
| `battery` | number | 是 | 已转 `float`（SDK 返回的是 `Decimal`，不转会导致 `jsonify` 崩） |
| `time` | string | 是 | 影子事件时间（UTC） |

**响应 502**

```json
{"ok": false, "error": "查影子失败: ..."}
```

**关键语义**：数据源是**设备影子**，不是实时推送。车在动时 5 秒一报、静止时 60 秒一报，所以：
- 车停着时 `time` 可能是 1 分钟前的
- `online:false` 时 `x/y` 是**最后一次**已知位置，别当实时值用

### I-03 `POST /command` —— 下发控制命令（同步）

**谁调**：APP 方向键 / 停止按钮；网页控制台按钮。
**底层**：后端调 `CreateCommand`（I-09），**阻塞等车端回执**，实测 300~400 ms，最长约 20 秒超时。

**请求**

```json
{"cmd": "FORWARD", "speed": 60}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `cmd` | string | 是 | `FORWARD` / `BACK` / `LEFT` / `RIGHT` / `STOP`，后端自动 `.upper()`，大小写不敏感 |
| `speed` | int | 仅 `FORWARD`/`BACK` | **0~100 的整数**（`60.0`、`"60"` 都不接受） |

`service_id` 由后端写死为 `car`，客户端不用传。

**响应 200**

```json
{"ok": true, "command_id": "5f8a...", "executed": true, "response_name": "FORWARD"}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `command_id` | string | 云端命令 ID，可拿去控制台排查 |
| `executed` | bool | **车端真的执行并回了回执才是 true**，不是"已发送" |
| `response_name` | string/null | 回执里带的命令名 |

> `ok:true` + `executed:false`：云端已受理但没等到回执（设备掉线/超时）。这时候别以为车动了。

**错误**

| 场景 | HTTP | 响应 |
|---|---|---|
| 命令不在白名单 | 400 | `{"ok":false,"error":"未知命令 DELETE_ALL，可选：['FORWARD','BACK','LEFT','RIGHT','STOP']"}` |
| `speed` 缺失/非整数/越界 | 400 | `{"ok":false,"error":"speed 必须是 0~100 的整数"}` |
| 请求体不是合法 JSON | 400 | 后端用 `get_json(silent=True)` → 当成 `{}` → `cmd` 为空 → 报"未知命令  " |
| 云端调用失败（凭证/端点/设备） | 502 | `{"ok":false,"error":"<SDK 异常原文>"}` |

审计：每条命令与回执都落到 `server/commands.log`。

### I-04 `GET /status`（视图端）

与 I-02 **完全同一个接口**，字段一致。差别只在客户端：

- `car_cloud_view.html`（`/view`）：**只读观察端**，v1.4 起主用 I-17 `/fleet_status` + I-16 `/devices` 拿全部车辆同屏显示；**绝不调 `/command`**
- `car_console.html`（`/`）：同样用 `/fleet_status` + `/devices`，但额外会调 `/command` / `/voice_command`，且始终只针对一台「当前控制」车

两者轮询间隔同为 `POLL_MS = 2000`。`/status` 现在只作**兜底**：批量接口 404 时，两个页面各自退回逐台 `/status?device_id=`。

### I-05 `POST /command`（视图端）

与 I-03 同一接口。浏览器发 JSON 会触发 **OPTIONS 预检**，所以后端补了 `Access-Control-Allow-Headers: Content-Type`——只有 `Allow-Origin` 时预检必失败，请求根本发不出去（这是本项目踩过的坑）。

### I-06 `GET /`、`/console`、`/view` —— 页面分发

| 路径 | 返回 | 说明 |
|---|---|---|
| `/`、`/console` | `web/car_console.html` | 可看可控的控制台（多车同屏 + 速度滑块 + D-pad + 指令记录 + AI 语音） |

双击本地文件（`file://`）打开也能用，走的是另一条路——后端 CORS 已放行。

### I-15 `POST /voice_command` —— 自然语言控车（2026-11-08 新增）

**谁调**：网页控制台的语音按钮 / 文字输入框；鸿蒙 APP 后续可复用同一接口。
**底层**：后端三段式链路 `ASR → DeepSeek → 规则裁决`，AI 服务密钥只留在后端，客户端零持有。

```
语音采集 → 16k WAV → ASR 文本 → DeepSeek JSON → 白名单裁决 → I-03 /command → I-09 → MQTT
```

**请求（二选一）**

| 形式 | Content-Type | 内容 |
|---|---|---|
| 录音 | `multipart/form-data` | `audio` = 16kHz / 单声道 / 16bit PCM 的 WAV（≤5MB），可附 `execute` |
| 文本兜底 | `application/json` | `{"text": "往前开慢一点", "execute": false}`，跳过 ASR |

网页端用 Web Audio 直接产出 16k WAV，与鸿蒙 `AudioCapturer` 的参数完全一致。麦克风必须在 **HTTPS 或 localhost** 下才可用；用 `http://<局域网IP>:8000/` 打开时页面会明确提示改用文字输入。

**响应 200**（解析失败也返回 200，便于前端逐层展示中间结果）

```json
{
  "ok": true,
  "text": "往前开慢一点",
  "parsed": {"cmd": "FORWARD", "speed": 30, "confident": true},
  "command": {"cmd": "FORWARD", "speed": 30},
  "stage": "",
  "error": null,
  "timings": {"asr_ms": 1936, "llm_ms": 1175},
  "auto_execute": false,
  "executed": false
}
```

| 字段 | 说明 |
|---|---|
| `text` | ASR 识别的原文，或请求里直接给的 text |
| `parsed` | **大模型原始输出**，未经裁决，仅供展示与排错 |
| `command` | **裁决后**才允许的规范指令；`null` 表示拒绝执行 |
| `stage` | 异常发生在哪一段：`asr` / `llm` / `validate` / `input` / `dispatch`；全部成功为空串 |
| `auto_execute` | 本次请求是否要求自动下发 |
| `executed` | **唯一可信的「车真的动了」标志**：仅当 I-09 拿到车端回执才为 `true`，默认 `false` |
| `dispatch` | 自动执行时的 I-09 下发结果（含 `command_id`），或 `{"error": ...}` |
| `dispatch_error` | 自动执行但下发失败的原因，例如设备离线 `IOTDA.014016` |
| `timings` | ASR 与大模型各自耗时，课堂上用来讲"延迟从哪来" |

> **语义澄清（v1.2）**：`ok` 只表示 `ASR → DeepSeek → 规则裁决` 这一段解析成功，**不代表车已执行**。是否真的下发成功必须看 `executed` / `dispatch_error`。解析成功 ≠ 已下发 ≠ 已执行，三者前端日志分开记录，不许混写 `executed=true`。

**安全约束（重点）**

- `parsed` 永不直接执行；必须经 `validate()` 校验 `cmd ∈ 五条白名单`、`FORWARD/BACK 的 speed ∈ 0~100 整数`、`confident !== false`。
- 自动执行默认关闭（`config.json → voice.auto_execute=false`），前端解析后需人工点"执行该指令"，实际走的仍是 I-03 `/command`。
- 若 `execute=true` 或后端开启 `auto_execute`，后端内部复用 I-09 下发逻辑，并**再过一次** `/command` 的白名单校验（双保险）。
- 紧急停车保留物理按钮，不经过 AI 链路。

**典型失败**

| 现象 | stage | 处理 |
|---|---|---|
| 合成音 / 静音 | `asr` | "没有识别到语音内容"，用真实人声重试 |
| 与开车无关 / 一句话两个动作 | `validate` | LLM 输出 `cmd:null`，裁决层拒绝并提示重说 |
| 大模型超时或欠费 | `llm` | 检查 `config.json → llm`；文字兜底可绕过 ASR 但绕不过 LLM |
| **设备离线**（`execute=true`） | `dispatch` | 解析仍成功、`ok=true`，但 `executed=false` 且带 `dispatch_error`：`IOTDA.014016 Operation not allowed. The device is not online.` 重启车端 `car_mqtt_client_001.py` 后再试 |
| 语音链路被关 | 503 | `config.json → voice.enabled=false` |

**体检脚本**：`server/test_voice_api.py`，逐项验证 DeepSeek 文本接口、MaaS 模型列表、ASR 的 HTTP 与 WebSocket 两条通道。

### I-16 `GET /devices` —— 设备台账（2026-11-08 M1 新增）

**谁调**：网页控制台右上角选车下拉；后续 B/S 管理台、APP 选车页。
**底层**：读本机 `server/devices.json`，**不调云 API** —— N 台车就是 N 次 `ShowDevice` 同步调用，2 秒轮询会被拖垮；批量状态统一改走 I-17 `/fleet_status`，单台仍可用 I-02 `/status`。

**请求**：无参数。

**响应 200**

```json
{
  "ok": true,
  "default": "6aeedf21cbb0cf6bb995299d_mycar_001",
  "devices": [
    {"device_id": "6aeedf21cbb0cf6bb995299d_mycar_001", "name": "1 号车",
     "kind": "simulator", "group": "课堂演示", "enabled": true, "default": true},
    {"device_id": "6aeedf21cbb0cf6bb995299d_mycar_002", "name": "2 号车",
     "kind": "simulator", "group": "课堂演示", "enabled": true, "default": false}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `default` | 不传 `device_id` 时服务端回落到这台车 |
| `devices[].kind` | `simulator` / `real`，区分模拟车与真车 |
| `devices[].group` | 分组，为后续按班组授权预留 |
| `devices[].enabled` | `false` 的车仍列出但不可控，服务端返回 400 |

> **`devices.json` 只存元数据，绝不写 AK/SK 或设备密钥** —— 这份数据会原样发到前端。设备密钥仍只在各 `car_mqtt_client_00X.py` 里。第二台车 `mycar_002` 于 2026-11-08 用应用侧 `AddDevice`（产品 `oh-car`，`product_id=6aeedf21cbb0cf6bb995299d`）注册。

**v1.5 起**：`/devices` 按身份可见范围过滤，每台车带 `can_control`（见「鉴权约定」与 I-18）。台账仍只存元数据，**绝不写 token**。绑定关系的维护入口是 `server/access_admin.py`；B/S 管理台留到 M4。（N 台车批量状态聚合已由 I-17 落地。）

### I-17 `GET /fleet_status` —— 批量状态（2026-11-08 多车同屏新增）

**谁调**：网页控制台（`/`）、只读俯视图（`/view`）各每 2 秒一次；后续 B/S 管理台的车队列表。**一次 HTTP 拿回台账里全部 `enabled=true` 的车**，前端不必对每台车各发一次 `/status`。

**为什么需要**：N 台车逐台查 = N 个 HTTP + 2N 次云 API（每台车 `ShowDeviceShadow` + `ShowDevice`），2 秒轮询很快打满。服务端用 `ThreadPoolExecutor` 并发查询，并用 1 秒短缓存让多个页面 / 多次轮询共用同一份快照；缓存比轮询周期短，不会读到太旧的数据。

**请求**：无参数，**不带 `device_id`**（本接口语义就是"全部车"）。

**响应 200**（每条 `devices[]` 的形状与 I-02 `/status` 一致，额外带 `ok` / `name` / `kind` / `group`）

```json
{
  "ok": true,
  "default": "6aeedf21cbb0cf6bb995299d_mycar_001",
  "devices": [
    {"device_id": "..._mycar_001", "name": "1 号车", "ok": true, "online": true,
     "x": 414, "y": 226, "heading": 345, "speed": 0, "battery": 86.5,
     "time": "20261108T091009Z", "kind": "simulator", "group": "课堂演示", "default": true},
    {"device_id": "..._mycar_002", "name": "2 号车", "ok": true, "online": true,
     "x": 228, "y": 136, "heading": 15, "speed": 0, "battery": 86.9,
     "time": "20261108T091101Z", "kind": "simulator", "group": "课堂演示", "default": false}
  ],
  "elapsed_ms": 265,
  "cached": false
}
```

| 字段 | 说明 |
|---|---|
| `devices[].ok` | **单台**查询是否成功；失败时带 `error`，其它车照常返回，不会被一台车拖垮整批 |
| `devices[].online` | 该设备是否在线；离线车前端半透明显示，影子只是历史值 |
| `devices[].time` | 影子原始上报时间（UTC），前端据此显示「几分钟前」而非「0 秒前」 |
| `cached` | `true` 表示命中 1 秒缓存，未再打云 API |
| `elapsed_ms` | 本批查询耗时，课堂上用来讲"并发 vs 串行" |

**前端契约**：控制台把状态从"单车一个变量"改成 `fleet[]`，每台车独立持有影子 / 航位推算 / 轨迹 / 颜色；画布同屏绘制全部车辆，每台带名字标签，**当前控制对象**用虚线光环标出。切换控制对象（下拉 / 点画布 / 点车队卡片）**不清空其它车的状态**。命令类接口仍只带一个 `device_id`，**绝不广播**——同屏显示 ≠ 同时控制。

**只读端（`/view`，v1.4 起）**：同样用 `fleet[]` 同屏绘制，但**没有「当前控制」概念**、没有光环、页面里不存在任何 `/command` 调用或控制按钮。HUD 从单车数值改成**车队汇总**（登记 / 在线 / 行驶中 / 最低电量 / 最旧影子上报 / 本次刷新耗时），下方「车队状态」每台车一行。顺带修掉老版把「距上次轮询多久」误显示为「影子更新距今」的问题——现在用影子 `event_time`(UTC) 算真实年龄，离线几小时会如实显示。

**向后兼容**：`/fleet_status` 返回 404（未重启的旧后端）时，前端自动退回逐台 `/status?device_id=...` 并发查询；`/devices` 404 时退回原来的单车界面。因此后端不重启也能看到多车，只是没有并发聚合与缓存。

**实测（2026-11-08 17:12）**：两车在线，批量接口 265 ms 返回、第二次调用 `cached=true`；002 下发 `FORWARD 30` 后 `speed=30`、坐标 (228,136)→(230,130)，001 仍 `speed=0` / (414,226)，互不串台；已补 `STOP`。

### I-18 `GET /whoami` —— 当前身份与授权范围（2026-11-08 M2 新增）

**谁调**：网页控制台在应用令牌前校验一次；鸿蒙 APP 设置面板「应用」时校验；后续 B/S 管理台展示当前登录者。
**底层**：只读 `access.json` + `devices.json`，**不调云 API**，也**不返回任何 token**。

**请求**：无参数；可带 `X-Auth-Token`。

**响应 200**

```json
{
  "ok": true,
  "actor": {
    "user": "guest", "name": "访客（未登录）", "role": "operator", "scope": "all",
    "auth_enabled": true,
    "can_control": ["6aeedf21cbb0cf6bb995299d_mycar_001"],
    "visible": ["6aeedf21cbb0cf6bb995299d_mycar_001", "6aeedf21cbb0cf6bb995299d_mycar_002"]
  },
  "require_token": false
}
```

| 字段 | 说明 |
|---|---|
| `actor.can_control` | 当前身份**能下发**的 device_id 列表；前端据此标「只读」，真正裁决仍在服务端 |
| `actor.visible` | 当前身份**能看见**的 device_id 列表；`/devices` 与 `/fleet_status` 据此裁剪 |
| `actor.role` | `admin` / `operator` 可控制，`viewer` 只读 |
| `require_token` | 后端是否处于严格模式（不带 token 一律 401） |

**典型失败**

| 现象 | 状态码 | 原因 |
|---|---|---|
| `stage=auth` | 401 | token 无效，或严格模式下没带 token |
| `stage=auth` | 403 | 账号被 `access_admin.py disable` 停用 |

**客户端契约**

- 网页控制台：令牌存 `localStorage.carAuthToken`，所有请求经 `apiFetch()` 自动带 `X-Auth-Token`；越权 403 如实显示并写指令记录，**不自行放行**。
- 只读俯视图 `/view`：同源复用同一份令牌，只显示身份，不提供输入框、不调任何写接口。
- 鸿蒙 APP：设置面板「应用 / 退出」，令牌与选中的 `device_id` 用 `PersistentStorage` 持久化；`/status` 与 `/command` 都带身份和 `device_id`；旧后端 `/devices`、`/whoami` 返回 404 时自动退回单车模式。

**绑定关系维护**（`server/access_admin.py`，改完热加载生效）：`list` 查看、`grant/revoke <user> <device_id|*>` 授权解绑、`rotate <user>` 轮换 token、`enable/disable`、`scope <user> all|bound`、`strict on|off`。

**实测（2026-11-08 17:48）**：访客 → 可控 1 / 可见 2；访客控 002 → 403 `stage=auth`；教师 token 控 002 → `executed:true`；无效 token → 401；语音链路指向 002 → 403；`commands.log` 留下 `越权拒绝 -> user=guest device=…`。

### I-19 `GET /field` —— 场地坐标系与合规底图（2026-11-08 M3 新增）

配置源文件 `server/field.json`，按 mtime 热加载；前端同构库 `web/field.js` 用同一套公式。

| 字段 | 含义 |
|---|---|
| `logical` | 逻辑坐标：800×600，左上 (0,0)，x 向右 / y 向下，与车端影子上报完全一致 |
| `scale.meters_per_unit` | 1 逻辑单位 = 多少米（默认 0.025 m ⇒ 场地 20 m × 15 m） |
| `zones` | 本地自绘矢量分区：待命区 / 禁行区 / 巡检主通道 / 充电位 |
| `geofence` | 安全边界多边形 + 内缩 margin；任务启动前校验车辆在界内 |
| `waypoints` | 巡检点 P1/P2/P3（逻辑坐标） |
| `geo` | `enabled` / `calibrated` / `datum=GCJ-02` / 原点经纬度 / 方位角 |
| `compliance` | 底图合规声明、允许与禁止的服务商清单、密钥规则 |

**位置映射结果**：`/status` 与 `/fleet_status` 的每台车新增 `pos`：

```json
{
  "x": 400, "y": 300, "mx": 10.0, "my": -7.5,
  "inside": true, "zone": "禁行区（设备柜）", "restricted": true,
  "geo": null, "unit": "m"
}
```

`mx/my` 是以场地原点为基准的东 / 北米制坐标；`geo` 只有在 `geo.enabled=true && geo.calibrated=true` 时才输出 GCJ-02 经纬度，**未校准一律为 null**，避免把示例原点 (0,0) 当成真实位置。观察员（role=viewer）拿到的配置里基准点会被抹掉。

**合规约束**：默认底图是本地自绘矢量场地，不加载任何在线瓦片、不绘制国界与行政区划；真实地理底图只在 `/map` 使用腾讯位置服务 GL JS 官方 key 代理模式（页面零密钥、SDK URL 不带 key），允许的服务商仅限腾讯位置服务 / 高德 / 百度 / 天地图，禁止 Google Maps、Apple Maps、Bing 海外版、OSM 境外瓦片、Mapbox、Leaflet+OSM。

### I-20 `GET/POST /mission*` —— 任务级指令编排（2026-11-08 M3 新增）

把多条规范指令编成一个可观测、可急停的任务。实现在 `server/mission.py`，后台线程执行，事件追加写 `server/missions.log`。

| 接口 | 方法 | 说明 |
|---|---|---|
| `/mission/presets` | GET | 4 个预设：`square` 矩形巡检 / `out_back` 直线往返 / `patrol` 通道巡检 / `selfcheck` 原地自检，附步骤与预计时长 |
| `/mission` | POST | `{"device_id":"...","preset":"square"}` 或 `{"device_id":"...","name":"...","steps":[{"cmd":"FORWARD","speed":50,"duration_ms":1200}]}` → 202 + `mission` |
| `/missions` | GET | 最近 20 个任务摘要 |
| `/mission/<id>` | GET | 单个任务详情（含 `results[]`、`trail[]`、`progress`） |
| `/mission/<id>/cancel` | POST | 取消并**异步下发 STOP 急停**；只能取消本人任务，admin 可取消全部 |
| `/mission/abort_all` | POST | 一键全停所有进行中任务（admin；未开鉴权时放行） |

**任务对象关键字段**：`id / name / device_id / actor / state / index / total_steps / results / trail / error`。`state` 取值 `pending → running → succeeded | failed | cancelled`（取消瞬间会先置 `cancelling`）。`results[]` 每步记录 `cmd / paras / command_id / executed / error / elapsed_ms`；`trail[]` 每步后采样影子位置并带上 I-19 的 `pos`。

**安全的五条硬约束**

1. 同一台车同时只允许一个 `pending/running` 任务，第二个请求 400「避免两个任务抢方向盘」。
2. 每一步下发前**重新读 access.json** 校验 `(身份, device_id)`；任务跑一半被 `revoke` / 停用账号会立刻 `failed`。
3. 步骤只认五条白名单指令，不接受自然语言；`speed` 0~100、`duration_ms` 100~5000、步骤 ≤20、总时长 ≤60 s。
4. 启动前车辆必须在 geofence 内；越界拒绝启动（急停不受此限制）。
5. 成功或失败都**自动下发 STOP** 收尾；取消时立即异步发 STOP；物理/直连急停入口不受影响。

**典型失败**：`{"ok":false,"stage":"validate","error":"第 1 步命令不合法：FLY"}`（400）、越权 403、同一车并发 400。

## 4. ②→③ 后端调用华为云 OpenAPI

### 认证三要素（缺一必 403）

```python
credentials = BasicCredentials(ak, sk, project_id)
credentials.with_derived_predicate(DerivedCredentials.get_default_derived_predicate())  # ② 衍生签名
client = IoTDAClient.new_builder() \
    .with_credentials(credentials) \
    .with_region(Region(region, endpoint)) \      # ① 实例专属端点
    .build()
# ③ 请求里【不带】instance_id
```

| 要素 | 正确做法 | 错了会怎样 |
|---|---|---|
| ① 端点 | `https://9f149bee02.st1.iotda-app.cn-north-4.myhuaweicloud.com` | 用通用域名 `iotda.cn-north-4...` → 恒定 403 |
| ② 签名 | `with_derived_predicate(...)` | 漏配 → 验签失败，但报错文案甩锅给"用户不存在" |
| ③ 参数 | 不带 `instance_id` | 带了 → 403（实例已在域名里） |

`403 IOTDA.000021` 就是这三项之一出错，报错信息"User not found by IAM token or not subscribed to IoTDA"**极具误导性，别去查权限**。用 `server/test_api_auth.py` 跑一遍矩阵即可定位。

---

### I-07 `ShowDevice` —— 查设备详情

| 项 | 值 |
|---|---|
| 入参 | `ShowDeviceRequest(device_id="6aeedf21..._mycar_001")` |
| 取用字段 | `resp.status` ∈ `ONLINE` / `OFFLINE` / `INACTIVE` |
| 被谁用 | `/health`（I-01）、`/status`（I-02） |
| 异常处理 | `SdkException` → 记日志 → 返回 `false`（降级，不抛给客户端） |

---

### I-08 `ShowDeviceShadow` —— 读设备影子

| 项 | 值 |
|---|---|
| 入参 | `ShowDeviceShadowRequest(device_id=...)` |
| 取用字段 | `shadow[].reported.properties`（5 属性）+ `shadow[].reported.event_time` |
| 被谁用 | `/status`（I-02） |
| 特殊处理 | `battery` 是 `Decimal`，必须 `float()` 转换，否则 `jsonify` 报错（本项目踩过） |

响应压平逻辑在 `app.py` 的 `shadow_to_state()`：只取 `reported`，不取 `desired`；多服务时取第一个带属性的。

### I-09 `CreateCommand` —— 下发命令（同步）

```python
CreateCommandRequest(
    device_id=CFG["device_id"],
    body=DeviceCommandRequest(
        service_id="car",          # 物模型里的服务 ID，写死
        command_name="FORWARD",
        paras={"speed": 60},       # 无参命令也必须传 {}，传 None 报 IOTDA.000006
    ),
)
```

| 项 | 值 |
|---|---|
| 返回 | `resp.command_id`、`resp.response`（有值=车已回执） |
| 判定 | `executed = bool(response.response_name)` |
| 坑 | `resp.response` 反序列化后**可能是 dict 也可能是模型对象**，两种都要兼容 |
| 超时 | 同步命令默认等车端回执，约 20 秒 |

## 5. ③↔④ 云端与小车：MQTT

### I-10 CONNECT 鉴权（一机一密）

```
timestamp = UTC 时间，格式 YYYYMMDDHH     ← 必须是 UTC，不是北京时间
password  = HMAC-SHA256(key=timestamp, msg=secret) 的十六进制
clientId  = {device_id}_0_1_{timestamp}
username  = {device_id}
```

| 项 | 值 |
|---|---|
| 地址 | `9f149bee02.st1.iotda-device.cn-north-4.myhuaweicloud.com` |
| 端口 | `8883`（MQTTS / TLS） |
| keepalive | 120 秒 |
| QoS | 1 |
| 典型失败 | `rc=4` 鉴权失败（HMAC 参数顺序反了 / 时间戳用了北京时间）；`rc=5` 未授权 |

> 教学脚本用 `cert_reqs=CERT_NONE` 跳过证书校验。生产环境必须校验证书，否则等于裸奔。

**同一 `device_id` 只允许一条 MQTT 连接**：跑两份客户端会互踢，控制台手动"模拟设备"也会踢掉脚本。

---

### I-11 SUBSCRIBE 命令主题

```
$oc/devices/{device_id}/sys/commands/#        qos=1
```

通配 `#` 是为了同时收下发给该设备的各类命令（含带 `request_id` 后缀的响应主题同族）。

---

### I-12 命令下发（云端 → 小车）

**主题**：`$oc/devices/{device_id}/sys/commands/request_id={request_id}`

**payload**（小车只取其中两个字段）：

```json
{
  "service_id": "car",
  "command_name": "FORWARD",
  "paras": {"speed": 60},
  "command_id": "...",
  "request_id": "..."
}
```

**`request_id` 在主题尾部**，不在 payload 里——要靠 `topic.split("/")` 取，回执主题要用它。

小车动作：`apply_command()` → 改运动模型（`FORWARD/BACK` 设速度、`LEFT/RIGHT` 转 15°、`STOP` 归零）→ 回执 → **立即上报一帧**。

---

### I-13 命令响应（小车 → 云端）

**主题**：`$oc/devices/{device_id}/sys/commands/response/request_id={request_id}`

```json
{"result_code": 0, "response_name": "FORWARD"}
```

`result_code=0` 表示执行成功。这条回执正是后端 `executed:true` 的唯一依据：回执不来，前端就只能拿到 `executed:false`。

---

### I-14 属性上报（小车 → 云端）

**主题**：`$oc/devices/{device_id}/sys/properties/report`

```json
{
  "services": [
    {"service_id": "car", "properties": {"x": 427, "y": 312, "heading": 135, "speed": 0, "battery": 83.2}}
  ]
}
```

**上报节奏**（省免费额度，S0 每天 1 万条）：

| 时机 | 间隔 |
|---|---|
| 运动中 | 5 秒 |
| 静止 | 60 秒（证明还活着） |
| 连上云、执行完命令 | 立即补一帧 |

云端收到后写入设备影子 → 后端的 `/status` 才读得到。**这条链路是"影子"三个字的全部含义**。

---

## 6. 一次 `FORWARD` 的完整旅程

以点一下 APP 的"前进"为例（实测 300~400 ms）：

| 时刻 | 端 | 发生什么 | 对应接口 |
|---|---|---|---|
| t+0 ms | ① APP | 按钮触发，禁用全部按钮防连点 | — |
| t+5 ms | ① → ② | `POST /command {"cmd":"FORWARD","speed":60}` | I-03 |
| t+15 ms | ② 后端 | 白名单校验通过，写 `commands.log` | — |
| t+30 ms | ② → ③ | `CreateCommand`（HTTPS + 衍生签名） | I-09 |
| t+120 ms | ③ 云端 | 查物模型 → MQTT 推给设备 | I-12 |
| t+200 ms | ④ 小车 | `car.speed = 60`，位置开始按 1s/格 推进 | — |
| t+210 ms | ④ → ③ | 回执 `{"result_code":0,"response_name":"FORWARD"}` | I-13 |
| t+215 ms | ④ → ③ | 立即上报一帧属性 | I-14 |
| t+280 ms | ③ → ② | 同步命令返回，`response_name` 有值 | I-09 |
| t+300 ms | ② → ① | `{"ok":true,"executed":true,...}` | I-03 |
| 之后 ≤2 s | ① APP | 下一次轮询拿到新 `x/y`，画布上车位置跳一下 | I-02 |

**为什么画布上会"漂移 + 白圈校正"**：APP 每 100 ms 自己按 `speed×0.2 px/s` 外推（航位推算），而真实坐标 5 秒才更新一次；白圈就是最近一次影子上报的真实点，数据到达时把漂移拉回来。

## 7. 故障定位表（按现象反查是哪一段断了）

| 现象 | 最可能断在 | 怎么查 |
|---|---|---|
| APP 顶部"后端不通" | ①→② | `curl http://127.0.0.1:8000/health`；后端进程是否在跑；地址/热点是否变 |
| `device_online:false`，但后端正常 | ④→③ | 小车终端是否还在跑；控制台设备是否 ONLINE；是否被第二份客户端踢掉 |
| `/status` 的 `x/y` 一直是 `null` | ③ 影子没数据 | 物模型是否上传；小车是否上报过；`time` 是否为 `null` |
| `/command` 返回 403 `IOTDA.000021` | ②→③ 认证 | 端点/衍生签名/instance_id 三要素，跑 `test_api_auth.py` |
| `/command` 返回 `executed:false` | ③→④ 下行 | 设备离线；`request_id` 没取到；车端脚本报错（看它的终端） |
| `/command` 返回 400 | ①→② 参数 | `cmd` 白名单、`speed` 必须 0~100 整数；**或** `device_id` 未在 `devices.json` 登记 / `enabled=false`（查 `GET /devices`） |
| 切换车辆后画面还是上一台车的位置 | ⑤ 渲染层 | 前端换车时要清空 `shadow/car/trail` 并重新 `poll()`，否则两台车航位推算画串 |
| 网页点按钮没反应、控制台报 CORS | ⑤→② 预检 | 后端是否带 `Allow-Headers`；是否重启过后端 |
| APP 指标全 `--` | ① 渲染层 | `/status` 是否返回 `null`；ArkUI 是否把值写死在 `@Builder` 里 |
| 坐标不动 | ④ 运动模型 | `speed` 是否为 0；`heading` 与位移方向是否符合"0=朝上" |

## 附：一句话记住每个端

- **① APP**：只管画和点，**零云凭证**，认一个 8000 端口。
- **② 后端**：唯一持有 AK/SK 的地方，三件事——挡非法命令、藏凭证、留审计。
- **③ IoTDA**：把"设备间歇在线"这件事抽象成影子，顺便校验物模型。
- **④ 小车**：MQTT 客户端（不是服务端），主动连云，收命令、报属性。
- **⑤ 视图端**：就是浏览器，同一套 HTTP 接口的另一个消费者。
