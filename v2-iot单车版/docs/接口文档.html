2数据契约（全链路统一）

所有端对同一组字段用同一套语义，改一处要五处同步。

字段类型范围含义
xnumber10 ~ 790场地横坐标（场地 800×600）
ynumber10 ~ 590场地纵坐标，向下增大
headingnumber0 ~ 359朝向，0 = 朝上，顺时针增大（90 = 朝右）
speednumber-100 ~ 100带符号：正 = 前进，负 = 后退，0 = 停
batterynumber20.0 ~ 100电量百分比，最低兜底 20.0
timestring—影子事件时间，UTC 紧凑格式 20261107T092226Z
方向约定：heading=0 朝上 → 前进时 y 减小，这是最容易看错的一点。
时间约定：云端一律 UTC；只有小车日志用本地时间。APP 里的"影子上报 N 秒前"就是拿 time 换算出 UTC 再求差的。

3①② 与 ⑤② 之间：HTTP 接口

三条业务接口对 APP 和网页是完全一样的，区别只在调用者：
· APP：@kit.NetworkKit 的 http，原生请求，没有 CORS 概念
· 网页：浏览器 fetch，受同源策略约束（本工程已解决，见 I-06）

通用约定

  • 基础地址：模拟器 http://10.0.2.2:8000；真机/网页 http://<电脑局域网IP>:8000；本机 http://127.0.0.1:8000
  • 请求头：Content-Type: application/json
  • 响应头：Access-Control-Allow-Origin: *、Allow-Headers: Content-Type、Allow-Methods: GET, POST, OPTIONS、Max-Age: 600
  • 错误响应统一形状：{"ok": false, "error": "人类可读的原因"}
  • 时间单位一律毫秒 / 秒在文档里写明，不靠猜
GET/health
探活 + 设备是否在线
GET/status
读设备影子（2 秒轮询）
POST/command
下发命令，同步等回执

I-01GET/health —— 探活 + 设备在线

谁调：APP 启动时打一次，用来点亮右上角"车在线"徽标。
底层：后端调一次 ShowDevice（I-07），看 status 字段。

请求：无参数、无 body。

响应 200

{"ok": true, "device_online": true}
字段类型说明
okbool后端自身存活（能返回就一定是 true）
device_onlinebool设备状态是否为 ONLINE；云端调用异常时降级为 false
注意：ok:true + device_online:false 是常见组合，意思是"后端活着，但小车没连上"。

I-02GET/status —— 拉最新状态

谁调：APP 每 2 秒轮询一次；网页同样 2 秒。
底层：后端调 ShowDeviceShadow（I-08）+ ShowDevice（I-07），一次请求打两次云 API。

请求：无参数。（页面用 fetch(url, {cache:'no-store'}) 禁用缓存，避免拿到旧坐标。）

响应 200

{
  "ok": true,
  "online": true,
  "x": 427,
  "y": 312,
  "heading": 135,
  "speed": 0,
  "battery": 83.2,
  "time": "20261107T092226Z"
}
字段类型可能为 null说明
okbool否—
onlinebool否设备当前是否在线
x / ynumber是影子里的坐标；设备从未上报过则为 null
headingnumber是0~359
speednumber是带符号
batterynumber是已转 float（SDK 返回的是 Decimal，不转会导致 jsonify 崩）
timestring是影子事件时间（UTC）

响应 502

{"ok": false, "error": "查影子失败: ..."}
关键语义：数据源是设备影子，不是实时推送。车在动时 5 秒一报、静止时 60 秒一报，所以：
· 车停着时 time 可能是 1 分钟前的
· online:false 时 x/y 是最后一次已知位置，别当实时值用

I-03POST/command —— 下发控制命令（同步）

谁调：APP 方向键 / 停止按钮；网页控制台按钮。
底层：后端调 CreateCommand（I-09），阻塞等车端回执，实测 300~400 ms，最长约 20 秒超时。

请求

{"cmd": "FORWARD", "speed": 60}
字段类型必填说明
cmdstring是FORWARD / BACK / LEFT / RIGHT / STOP，后端自动 .upper()，大小写不敏感
speedint仅 FORWARD/BACK0~100 的整数（60.0、"60" 都不接受）

service_id 由后端写死为 car，客户端不用传。

响应 200

{"ok": true, "command_id": "5f8a...", "executed": true, "response_name": "FORWARD"}
字段类型说明
command_idstring云端命令 ID，可拿去控制台排查
executedbool车端真的执行并回了回执才是 true，不是"已发送"
response_namestring/null回执里带的命令名
ok:true + executed:false：云端已受理但没等到回执（设备掉线 / 超时）。这时候别以为车动了。

错误

场景HTTP响应
命令不在白名单400{"ok":false,"error":"未知命令 DELETE_ALL，可选：['FORWARD','BACK','LEFT','RIGHT','STOP']"}
speed 缺失 / 非整数 / 越界400{"ok":false,"error":"speed 必须是 0~100 的整数"}
请求体不是合法 JSON400后端用 get_json(silent=True) → 当成 {} → cmd 为空 → 报"未知命令 "
云端调用失败（凭证 / 端点 / 设备）502{"ok":false,"error":"<SDK 异常原文>"}

审计：每条命令与回执都落到 server/commands.log。

I-04GET/status（视图端）

与 I-02 完全同一个接口，字段一致。差别只在客户端：

  • car_cloud_view.html（/view）：只读，只轮询 /status
  • car_console.html（/）：轮询 /status + 会调 /command

轮询间隔同为 POLL_MS = 2000。

I-05POST/command（视图端）

与 I-03 同一接口。浏览器发 JSON 会触发 OPTIONS 预检，所以后端补了 Access-Control-Allow-Headers: Content-Type —— 只有 Allow-Origin 时预检必失败，请求根本发不出去（这是本项目踩过的坑）。

I-06GET/、/console、/view —— 页面分发

路径返回说明
/、/consoleweb/car_console.html可看可控的控制台（速度滑块 + D-pad + 指令记录）
/viewweb/car_cloud_view.html只读俯视图
为什么要后端托管页面：页面与接口同源 → 浏览器根本不触发 CORS 检查，也顺便解决"手机连同一热点就能操作"的问题（打开 http://172.20.10.2:8000/ 即可）。
双击本地文件（file://）打开也能用，走的是另一条路 —— 后端 CORS 已放行。

4②→③ 后端调用华为云 OpenAPI

认证三要素（缺一必 403）

credentials = BasicCredentials(ak, sk, project_id)
credentials.with_derived_predicate(DerivedCredentials.get_default_derived_predicate())  # ② 衍生签名
client = IoTDAClient.new_builder() \
    .with_credentials(credentials) \
    .with_region(Region(region, endpoint)) \      # ① 实例专属端点
    .build()
# ③ 请求里【不带】instance_id
要素正确做法错了会怎样
① 端点https://9f149bee02.st1.iotda-app.cn-north-4.myhuaweicloud.com用通用域名 iotda.cn-north-4… → 恒定 403
② 签名with_derived_predicate(…)漏配 → 验签失败，但报错文案甩锅给"用户不存在"
③ 参数不带 instance_id带了 → 403（实例已在域名里）
403 IOTDA.000021 就是这三项之一出错，报错信息 "User not found by IAM token or not subscribed to IoTDA" 极具误导性，别去查权限。用 server/test_api_auth.py 跑一遍矩阵即可定位。

I-07APIShowDevice —— 查设备详情

项值
入参ShowDeviceRequest(device_id="6aeedf21..._mycar_001")
取用字段resp.status ∈ ONLINE / OFFLINE / INACTIVE
被谁用/health（I-01）、/status（I-02）
异常处理SdkException → 记日志 → 返回 false（降级，不抛给客户端）

I-08APIShowDeviceShadow —— 读设备影子

项值
入参ShowDeviceShadowRequest(device_id=...)
取用字段shadow[].reported.properties（5 属性）+ shadow[].reported.event_time
被谁用/status（I-02）
特殊处理battery 是 Decimal，必须 float() 转换，否则 jsonify 报错（本项目踩过）

响应压平逻辑在 app.py 的 shadow_to_state()：只取 reported，不取 desired；多服务时取第一个带属性的。

I-09APICreateCommand —— 下发命令（同步）

CreateCommandRequest(
    device_id=CFG["device_id"],
    body=DeviceCommandRequest(
        service_id="car",          # 物模型里的服务 ID，写死
        command_name="FORWARD",
        paras={"speed": 60},       # 无参命令也必须传 {}，传 None 报 IOTDA.000006
    ),
)
项值
返回resp.command_id、resp.response（有值 = 车已回执）
判定executed = bool(response.response_name)
坑resp.response 反序列化后可能是 dict 也可能是模型对象，两种都要兼容
超时同步命令默认等车端回执，约 20 秒

5③↔④ 云端与小车：MQTT

I-10CONNECT鉴权（一机一密）

timestamp = UTC 时间，格式 YYYYMMDDHH     ← 必须是 UTC，不是北京时间
password  = HMAC-SHA256(key=timestamp, msg=secret) 的十六进制
clientId  = {device_id}_0_1_{timestamp}
username  = {device_id}
项值
地址9f149bee02.st1.iotda-device.cn-north-4.myhuaweicloud.com
端口8883（MQTTS / TLS）
keepalive120 秒
QoS1
典型失败rc=4 鉴权失败（HMAC 参数顺序反了 / 时间戳用了北京时间）；rc=5 未授权
教学脚本用 cert_reqs=CERT_NONE 跳过证书校验。生产环境必须校验证书，否则等于裸奔。
同一 device_id 只允许一条 MQTT 连接：跑两份客户端会互踢，控制台手动"模拟设备"也会踢掉脚本。

I-11SUBSCRIBE命令主题

$oc/devices/{device_id}/sys/commands/#        qos=1

通配 # 是为了同时收下发给该设备的各类命令（含带 request_id 后缀的响应主题同族）。

I-12PUBLISH命令下发（云端 → 小车）

主题：$oc/devices/{device_id}/sys/commands/request_id={request_id}

payload（小车只取其中两个字段）：

{
  "service_id": "car",
  "command_name": "FORWARD",
  "paras": {"speed": 60},
  "command_id": "...",
  "request_id": "..."
}
request_id 在主题尾部，不在 payload 里 —— 要靠 topic.split("/") 取，回执主题要用它。

小车动作：apply_command() → 改运动模型（FORWARD/BACK 设速度、LEFT/RIGHT 转 15°、STOP 归零）→ 回执 → 立即上报一帧。

I-13PUBLISH命令响应（小车 → 云端）

主题：$oc/devices/{device_id}/sys/commands/response/request_id={request_id}

{"result_code": 0, "response_name": "FORWARD"}

result_code=0 表示执行成功。这条回执正是后端 executed:true 的唯一依据：回执不来，前端就只能拿到 executed:false。

I-14PUBLISH属性上报（小车 → 云端）

主题：$oc/devices/{device_id}/sys/properties/report

{
  "services": [
    {"service_id": "car", "properties": {"x": 427, "y": 312, "heading": 135, "speed": 0, "battery": 83.2}}
  ]
}

上报节奏（省免费额度，S0 每天 1 万条）：

时机间隔
运动中5 秒
静止60 秒（证明还活着）
连上云、执行完命令立即补一帧
云端收到后写入设备影子 → 后端的 /status 才读得到。这条链路是"影子"三个字的全部含义。

6一次 FORWARD 的完整旅程

以点一下 APP 的"前进"为例（实测 300~400 ms）：

时刻端发生什么对应接口
t+0 ms① APP按钮触发，禁用全部按钮防连点—
t+5 ms① → ②POST /command {"cmd":"FORWARD","speed":60}I-03
t+15 ms② 后端白名单校验通过，写 commands.log—
t+30 ms② → ③CreateCommand（HTTPS + 衍生签名）I-09
t+120 ms③ 云端查物模型 → MQTT 推给设备I-12
t+200 ms④ 小车car.speed = 60，位置开始按 1s/格 推进—
t+210 ms④ → ③回执 {"result_code":0,"response_name":"FORWARD"}I-13
t+215 ms④ → ③立即上报一帧属性I-14
t+280 ms③ → ②同步命令返回，response_name 有值I-09
t+300 ms② → ①{"ok":true,"executed":true,...}I-03
之后 ≤2 s① APP下一次轮询拿到新 x/y，画布上车位置跳一下I-02
为什么画布上会"漂移 + 白圈校正"：APP 每 100 ms 自己按 speed×0.2 px/s 外推（航位推算），而真实坐标 5 秒才更新一次；白圈就是最近一次影子上报的真实点，数据到达时把漂移拉回来。

7故障定位表（按现象反查是哪一段断了）

现象最可能断在怎么查
APP 顶部"后端不通"①→②curl http://127.0.0.1:8000/health；后端进程是否在跑；地址 / 热点是否变
device_online:false，但后端正常④→③小车终端是否还在跑；控制台设备是否 ONLINE；是否被第二份客户端踢掉
/status 的 x/y 一直是 null③ 影子没数据物模型是否上传；小车是否上报过；time 是否为 null
/command 返回 403 IOTDA.000021②→③ 认证端点 / 衍生签名 / instance_id 三要素，跑 test_api_auth.py
/command 返回 executed:false③→④ 下行设备离线；request_id 没取到；车端脚本报错（看它的终端）
/command 返回 400①→② 参数cmd 白名单、speed 必须 0~100 整数
网页点按钮没反应、控制台报 CORS⑤→② 预检后端是否带 Allow-Headers；是否重启过后端
APP 指标全 --① 渲染层/status 是否返回 null；ArkUI 是否把值写死在 @Builder 里
坐标不动④ 运动模型speed 是否为 0；heading 与位移方向是否符合"0=朝上"

8已知限制与扩展点

#限制现状扩展方式
1只认一台车device_id 写死在 config.json，三条接口都没有选设备参数接口加 ?device_id= 或 body 字段；后端做白名单映射
2后端无鉴权监听 0.0.0.0，同网段任何人可下发命令加一个 header token / 简易签名；教学环境可保持
3CORS 全放行Allow-Origin: *收紧到固定来源；同源托管后其实可以关掉
4无历史轨迹接口轨迹由前端自己攒加 GET /track?limit=500，后端把上报落库
5同步命令最长 20 秒前端会一直转圈改成异步：先拿 command_id，再轮询结果
6免费额度S0 每天 1 万条消息、1000 设备调上报间隔；或升配

附一句话记住每个端

  • ① APP：只管画和点，零云凭证，认一个 8000 端口。
  • ② 后端：唯一持有 AK/SK 的地方，三件事 —— 挡非法命令、藏凭证、留审计。
  • ③ IoTDA：把"设备间歇在线"这件事抽象成影子，顺便校验物模型。
  • ④ 小车：MQTT 客户端（不是服务端），主动连云，收命令、报属性。
  • ⑤ 视图端：就是浏览器，同一套 HTTP 接口的另一个消费者。
