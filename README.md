# 寻检车云控 · Harmony Car IoT

> 华为云 IoTDA 接入 + 鸿蒙 APP 远程控制 + AI 自然语言控车的全栈 IoT 教学项目。
> 课程《全场景智能寻检车 APP 开发实战》第三阶段配套工程（cloud 路线）。

一个从"点一下按钮"到"说一句话"都能开的智能寻检车系统：鸿蒙 APP / 浏览器发指令，
经业务后端鉴权中转，通过华为云 IoTDA 下发到模拟小车，车况再原路回流到界面。
项目按 M1→M4 四个里程碑演进，覆盖**双车同屏、绑定授权、场地任务编排、B/S 管理台、AI 语音控车**。

## 为什么是 v2：版本脉络

本项目是**分阶段教学工程**，每一阶段独立成一个工程，便于课堂对比演示。目录名 `v2-iot单车版`
中的 v2 指"第三阶段 / 云接入路线"，与前一阶段完全独立、互不覆盖：

| 阶段 | 工程 | 链路 | 小车角色 | 状态 |
|---|---|---|---|---|
| 第一阶段 | `lab01-tcp-sim`（TCP 直连） | APP ⇄ WebSocket ⇄ 小车 | TCP **服务端**，被动等人连 | 课堂教具，未纳入本仓库 |
| **第三阶段（本仓库）** | `v2-iot单车版`（IoTDA 云接入） | APP → 后端 → 华为云 → MQTT → 小车 | MQTT **客户端**，主动连云 | ✅ 本工程，四层闭环已打通 |

> 角色翻转是 MQTT 体系的核心知识点：**所有设备都是客户端，broker（IoTDA）才是服务端**。
> 命名里的"单车版"是历史叫法——项目后期已扩展为**双车**（见 M1），目录名保留仅为兼容文档中的引用。

## 功能一览

| # | 能力 | 说明 | 里程碑 |
|---|---|---|---|
| 1 | **四层控制闭环** | APP 点前进 → Flask → IoTDA → MQTT → 车动 → 回执原路返回，实测约 300ms | 基础 |
| 2 | **双车同屏** | 001 / 002 两台车在同一画布显示，各有独立影子/轨迹/颜色，切换控制对象不串台 | M1 |
| 3 | **绑定授权** | `X-Auth-Token` 身份 + 服务端逐次校验 `(身份, device_id)`；"可见"与"可控"分离，越权 403 留审计 | M2 |
| 4 | **场地与任务编排** | 米制坐标 + 本地矢量合规底图 + geofence；4 个预设任务逐步下发、逐步回执、可急停 | M3 |
| 5 | **B/S 管理台** | 账号绑定、令牌轮换、严格模式、设备启停、场地标定、任务监控、审计，一页统管 | M4 |
| 6 | **AI 语音控车** | 说话 → ASR 转文字 → DeepSeek 解析 → 规则裁决 → 白名单指令；解析成功 ≠ 已执行 | 增强 |
| 7 | **多端界面** | 鸿蒙 APP（ArkUI）、网页控制台 `/`、只读俯视图 `/view`、地理底图 `/map`、管理台 `/admin` | 全阶段 |

## 系统架构

```
   ① 鸿蒙 APP                                    ⑤ 浏览器（控制台 / 俯视图 / 管理台）
   @ohos.net.http 轮询                           fetch，同源托管
   零云凭证                                       零云凭证
        │  HTTP/JSON（I-01~06, I-15~22）              │
        └──────────────────┬─────────────────────────┘
                           ▼
                ② 业务后端 Flask  (app.py, :8000)
                凭证隔离 · 命令白名单 · 身份鉴权 · 审计日志
                           │  HTTPS OpenAPI（AK/SK 衍生签名，I-07~09）
                           ▼
                ③ 华为云 IoTDA（标准版 S0）
                设备影子 · 命令下发 · 物模型 · 一机一密
                           │  MQTTS / TLS :8883（I-10~14）
                           ▼
                ④ 模拟小车（car_mqtt_client_001 / 002.py）
                订阅命令 → 运动模型 → 上报 x/y/朝向/速度/电量
```

**核心设计原则：凭证只在需要它的那一层。** APP 和网页拿不到也存不了 AK/SK；
云端凭证只在后端，设备密钥只在本机凭证文件，AI 密钥只在后端配置。

**AI 语音链路**（三段式，出错能定位到具体一段）：

```
语音/WAV → ① ASR（阿里云 qwen-audio）→ 文本 → ② LLM（DeepSeek JSON Mode）
        → ③ 规则裁决（白名单 + 参数范围 + 置信度）→ 规范指令 → /command → MQTT
```

> 大模型的输出绝不直接执行；自动执行默认关闭，需人工确认。急停保留物理按钮，不经过 AI。

## 技术栈

| 层 | 技术 |
|---|---|
| 应用端 | HarmonyOS / ArkUI（API 22，HarmonyOS 6.0.2），`@ohos.net.http` |
| 视图端 | 原生 HTML / CSS / JavaScript，Canvas 俯视图与航位推算，无前端框架 |
| 业务后端 | Python 3.10 + Flask，ThreadPoolExecutor 并发查询 |
| 云平台 | 华为云 IoTDA 标准版 S0，设备影子 + 同步命令 |
| 设备端 | Python + `paho-mqtt`，一机一密 HMAC-SHA256 鉴权 |
| AI | 阿里云 DashScope（ASR）+ DeepSeek（LLM，JSON Mode） |
| 配置台账 | JSON 文件 + mtime 热加载 + 原子替换写 |

## 快速开始

### 1. 安装依赖

```bash
pip install paho-mqtt flask huaweicloudsdkiotda dashscope requests
```

### 2. 配置凭证（重要）

所有密钥都**不写在代码里**，只放本机、不进仓库。二选一：

- **方式 A（推荐）**：把 `v2-iot单车版/server/devices.local.example.json` 复制到
  `明文凭证/devices.local.json`，填入自己的设备 `secret`；后端 AK/SK 与 AI 密钥填入
  `v2-iot单车版/server/config.json`（参考 `docs/项目交接.md` 的参数表）。
- **方式 B**：用环境变量提供设备密钥，免去落盘：

  ```bash
  export IOTDA_SECRET_001=<1号车密钥>
  export IOTDA_SECRET_002=<2号车密钥>
  ```

换机器后只需重建这两个本地文件，不用改任何 `.py`。详见 `v2-iot单车版/server/credentials.py`。

### 3. 启动（先车端，再后端）

```bash
cd v2-iot单车版/server
python car_mqtt_client_001.py     # 终端 A：1 号车上云
python car_mqtt_client_002.py     # 终端 A2：2 号车上云（可选）
python app.py                     # 终端 B：业务后端
```

看到 `[连接] 已连上华为云 IoTDA` 和后端横幅即就绪。

### 4. 验证与体验

```bash
curl http://127.0.0.1:8000/health         # 探活
curl http://127.0.0.1:8000/fleet_status   # 全部车辆状态
curl -X POST http://127.0.0.1:8000/command \
  -H "Content-Type: application/json" \
  -d '{"cmd":"FORWARD","speed":60}'       # 下发命令（executed=true 才真执行）
```

浏览器打开：

| 地址 | 页面 |
|---|---|
| `http://127.0.0.1:8000/` | 控制台：多车同屏 + 方向键 + 速度 + AI 语音 + 任务面板 |
| `http://127.0.0.1:8000/view` | 只读俯视图：车队汇总，无任何控制入口 |
| `http://127.0.0.1:8000/map` | 合规地理底图（需现场标定 GCJ-02 基准点） |
| `http://127.0.0.1:8000/admin` | B/S 管理台：账号 / 设备 / 场地 / 审计 / 任务 |

> 鸿蒙 APP 工程（`ohcar`）为课堂配套工程，本机路径见 `docs/项目交接.md`；
> 模拟器后端地址默认 `http://10.0.2.2:8000`，真机改为电脑局域网 IP。

## 安全说明

- 本仓库为教学演示工程，**不是生产级**：文件台账、令牌明文无过期、无 HTTPS、CORS 全放行。
- 所有真实凭证（AK/SK、设备密钥、AI 密钥、身份令牌）均**不进仓库**，只存本机：
  `明文凭证/` 与 `server/config.json`、`server/access.json` 已被 `.gitignore` 排除。
- `devices.json` 只存设备元数据，**绝不写密钥**——`GET /devices` 会把它原样发给前端。
- 结课前请到 IoTDA 控制台冻结/删除演示设备、轮换或回收凭证。
- 地图合规：默认底图为本地自绘矢量，不加载在线瓦片；真实地理底图仅用合规服务商
  key 代理模式，未校准 GCJ-02 基准点时不输出经纬度。
